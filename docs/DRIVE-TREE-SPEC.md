# Drive Homebase — Tree Spec

Every book project gets one Drive homebase folder, created at project start. Proven on Harlow's Helping Paws (Nov 2026).

## Structure
```
<Book Title> — Project/
  START-HERE            (doc: what this project is, where everything lives, current status)
  Manuscripts/          (the author's draft iterations, under her exact dated filenames)
  Cast Finals/          (hi-res AI-upscaled masters ONLY — the print set)
  Recipes & Standards/  (character recipes, board standard, style locks)
  Cast — Working Canonicals/  (the working canonical portraits/full bodies the recipes point at)
  Project Docs/         (project-specific documents)
  Production Knowledge Base/  (the living production library — playbooks, Lulu sheets, checklists)
```

## Rules
- **Manuscript of record:** the author's own shared file stays the living source. A copy lives in Manuscripts for the project's records; her original is never replaced as the source. Story versions are tracked in the repo (`docs/STORY-VERSIONS.md`), not by hoarding manuscript copies.
- **Cast Finals holds masters only.** Working files, candidates, and superseded art never go there. Chat previews and web copies live elsewhere.
- **Shared inbox:** ONE Google Doc for all notes between the author and the production side, newest first. The author's side stays light by design — one pending list, never a gate.
- The homebase is the project's file home. The GitHub repo holds code and public pages, never the manuscript.
