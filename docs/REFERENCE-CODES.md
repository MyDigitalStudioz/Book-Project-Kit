# Reference codes — every reviewable item gets a permanent slot code

Locked 2026-11-20 (Jon + Trinity, on *Harlow's Helping Paws*). This is the naming system that lets a family review a book in conversation — by phone, in a car, over a screenshot — without anyone scrolling or describing pictures at each other.

## Why

The author reviews by phone and by voice. "Do you like R03?" has to be a complete question. Without codes, every review conversation drowns in descriptions ("the kitchen one — no, the other kitchen one"), and a code invented ad hoc in one chat drifts from the code used in the next. So the codes are assigned once, written onto the surfaces themselves, and never change.

## The rules

1. **Every reviewable item class gets a letter series.** One or two mnemonic letters per class, no collisions within the book. The class split follows how people actually compare things: covers split by face (fronts are judged against fronts, backs against backs), places split by kind (outdoor environments vs indoor rooms).
2. **A code names the SLOT, permanently.** The number is assigned in reading/story order when the item is adopted, and it belongs to the slot forever — never renumbered, never reused for a different item, even if the item is retired. R03 is the Common Room on every surface, in every conversation, for the life of the book.
3. **Revisions append a version suffix — `v2`, `v3`, …** — the same v-number style cast art takes already use. A repainted room is R03 v2; a revised cover front is F4 v2. The slot never moves; only the version climbs.
4. **First versions carry no suffix in conversation.** "R03" means the current R03. Records (recipes, production notes, dashboard) stay precise and name the version whenever one exists.
5. **Surfaces always show the current version.** A showcase card, deck slide, or review page displays the live take under its plain code. Superseded versions archive (the cast Archive pattern: demote, never delete) and are reachable through the records, not the surfaces.
6. **The code rides on the item.** Wherever the item appears for review — card caption, deck slide, selector chip, dashboard row — its code appears with its name ("E04 · Pony Field + Barn"). A code that lives only in a spreadsheet is not a code.

## The item classes

- **Places, split by kind:** outdoor **Environments** take `E` + number; indoor **Rooms** take `R` + number. (A lobby is a room; a habitat is an environment. When a space could be either, classify by where the camera stands — outside looking at it, or inside it.)
- **Covers, split by face:** **Fronts** take `F` + number, **Backs** take `B` + number, and a front/back pair shares its number — F4 and B4 are the two faces of one cover set.
- **Spreads:** `S` + the spread's number names the slot (S02, S12) on the spread-options pages. Alternates and revisions of a spread take the version suffix under the same slot-permanence rule — **S12 v2**. Book 1's letter-suffix alternates (S12-S, S15-R) are the **pre-standard form**: those pages are frozen records and keep their letters, but the vN rule replaces letter suffixes going forward. (SPREAD-OPTIONS-SYSTEM documents the legacy letter system in full.)
- **Background-cast figures:** people extras take `P` + number, animal extras take `A` + number, assigned in the extras sheet's recipe. Scene and spread briefs cite figures by ID ("P3 and A1 by the counter") so every scene's crowd is the same crowd. See CHARACTER-BOARD-STANDARD — the background/extras sheet.
- **Characters** are the exception that proves the rule: they have names, and names beat codes for people and animals with story roles. Codes are for the items whose names are long, similar, or easy to confuse — places, covers, spreads, extras.

## Assigning codes on a new book

Assign a class's codes in one pass, in story order, when the class's set is adopted — not one at a time as pieces land, or the numbers will encode arrival order instead of story order. Record the full mapping in the project's production notes and on the dashboard the same pass the codes first appear on a surface. Once a mapping is recorded, it is frozen: late additions take the next free numbers at the end of their series.
